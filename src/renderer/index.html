Quick Start & Connection Management

Use Quick Connect for temporary sessions, or save a connection when you need credentials, grouping, notes, monitoring, and workspace restore.

  1. Select + in the Connections sidebar and choose the category that matches the endpoint.
  2. Enter a name, host, protocol, and credentials. Advanced Settings contains port overrides, bastion metadata, keep-alive, reconnect, proxy, and pre-connect tasks.
  3. Double-click the saved node to connect. Right-click it for diagnostics, editing, duplication, screenshots, and external tools.

Fast navigation

Press Ctrl+K to fuzzy-search the vault, Alt+Space for the system-wide launcher, or paste a URI such as ssh://admin@10.10.1.12:22 into Quick Connect.

Import / Export

Open File → Import / Export. CyberGrid accepts mRemoteNG confCons.xml, PuTTY Registry exports, CSV, and encrypted .cgvault files.

  • Review imported profiles before first use; source formats may use different protocol defaults.
  • Plaintext mRemoteNG credentials are moved into central Vault Credential Profiles. Passwords encrypted by mRemoteNG itself still require re-entry.
  • CSV and PuTTY exports omit ordinary passwords. Use environment tokens such as ${USER_SECRET} for portable team trees.
  • .cgvault is the credential-preserving team format and requires its own strong passphrase.
  • For offline continuity, use the encrypted Disaster Recovery Runbook in Settings > Security.

SFTP Transfers & Config Backups

With an SSH tab active, select Tools → SFTP File Browser to browse the remote filesystem. Upload and download actions use the same authenticated SSH transport and display transfer progress.

Network configuration snapshots

Select a network device, open Tools → Node Workspace, then choose Config Backups. Paste or capture versioned output such as show running-config. Snapshots and notes remain encrypted in the vault.

Confirm the destination path and available space before transferring large files. CyberGrid does not overwrite remote files without using the selected destination name.

Broadcast Terminal (Multi-Exec)

Broadcast Mode mirrors input from the active primary SSH or serial terminal to explicitly selected connected targets.

  1. Open and verify every intended target session.
  2. Choose Tools → Broadcast Targets, filter by group, and review the target count.
  3. Enable Tools → Broadcast Terminal and enter the command in the primary terminal.
  4. Disable Broadcast immediately after the multi-host operation.

Start with a harmless identity command. Interactive prompts and shell state can differ between hosts, so destructive commands require a separate validation step.

Jump Hosts, SSH Tunnels & Auto-VPN

Advanced Settings stores bastion, proxy, and pre-connect orchestration per connection. Folder inheritance can provide common domain, key, and connection defaults to descendants.

  • Jump host: define the bastion endpoint and inherited credentials with the connection or parent folder.
  • SSH tunnel: create the tunnel as a pre-connect local task, then point the saved connection at the local forwarded endpoint.
  • Auto-VPN: assign a VPN profile or approved local script as a pre-connect task. Add a post-connect or cleanup task where the provider requires explicit teardown.
  • Proxy: global proxy settings apply to embedded Chromium tabs; native socket protocols continue to use their configured direct or task-established path.

Vault Security & Disaster Recovery

CyberGrid stores the encrypted vault, preferences, workspace layout, and audit logs in the operating system's per-user application-data directory—not beside the executable.

  • Master Password enabled: the password derives the AES-256-GCM vault key with scrypt and is required after launch or auto-lock.
  • Master Password disabled: a random automatic key is protected by the signed-in user's operating-system credential service through Electron safeStorage.
  • Auto-lock: configure the inactivity timeout and clipboard clearing interval in Settings > Security.
  • Workspace restore: only saved profile identifiers, the active position, and layout are persisted; decrypted credentials are never written to the workspace snapshot.
  • DR runbook: Settings > Security exports inventory, topology, notes, and configuration history as a fully encrypted offline HTML file. Store its passphrase separately.

Operational backup

Keep the encrypted vault, the OS-protected key or master password, and DR runbook backups in access-controlled locations. Test recovery periodically on an isolated workstation.
